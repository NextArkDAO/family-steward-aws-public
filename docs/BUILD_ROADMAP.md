## Next build sequence

### 1. Fictional household depth - complete

Add three bounded storylines so the demonstration shows repeat value instead
of one isolated form:

- school permission and schedule coordination;
- appointment preparation and a family calendar conflict;
- household renewal with a decision that Aster cannot make.

Expected proof: Aster remains quiet for routine preparation and produces one
concise interruption per genuine authority boundary.

### 2. QMD fictional memory projection - complete

Project only accepted fictional memory events into a dedicated Markdown
collection. Bind every document to an event ID, source digest, current state,
and allowed retrieval intent. QMD returns candidates; Family Steward verifies
them before use.

Expected proof: natural-language recall works when the question uses different
wording, while stale, foreign, or changed records fail closed.

### 3. One bounded Bedrock demonstration

Use the existing `family-steward` restricted profile and Amazon Nova Micro to
explain one deterministic decision packet. Do not give the model raw household
history, authority, or write access.

Expected proof: one successful call, exact identity receipt, redacted logs,
measured cost, and no surprise resources.

### 4. AWS demonstration architecture

Create only what the accepted demo requires:

- a small API surface for the household experience;
- encrypted synthetic persistence if local memory is insufficient;
- scale-to-zero compute;
- budget alerts and a hard-stop procedure;
- deployment proof for judging.

Do not add a persistent agent service, event scheduler, DynamoDB table, or
public endpoint until its product need is demonstrated locally.

### 5. Submission package

Prepare the architecture diagram, two-minute demonstration, truthful project
description, repository cleanup, AWS proof, cost receipt, privacy statement,
and rollback instructions.
